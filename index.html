🎯 Core Question

Does spending more inference compute (best-of-N, refinement) raise pass rate on coding tasks without training?

🔬 Hypothesis Draft

Under a fixed budget, sampling several cheap attempts + execution-based selection beats one expensive attempt and beats iterative self-refinement without ground truth.

📊 Key Deliverable

Cost–Performance Pareto curves comparing strategies across inference budgets, with bootstrap error bars and per-task outcomes.

🧠

Sharpened Problem Statement

Given a fixed dollar budget B and a verifier that cannot see the hidden tests, how should a coding agent split spend between independent samples, verification, and refinement to maximise the chance its final patch passes the hidden tests?

Prediction: Gain is bounded by oracle pass@N and by selector accuracy, so the best strategy depends on sample diversity and selector reliability.

Solution architecture: budget is split across samples, verification, and refinement; a selector picks the final patch without seeing hidden tests.

💰 Gate 1: After Pilot Spend Check

If one run costs c, full pass = 10c, pool of 8 = 80c. Pick model where 80c ≤ ~$60.

🛡️ Gate 2: Reserve Hard Cap

Keep ~$25 for verification calls, refinement, and infra reruns. Never spend the last $10.

🎯 Cost Trick Key Insight

Run an 8-sample pool once, then simulate best-of-N for N=1…8 by resampling. One pool → many budget points → tight paired comparisons. Assumption: sandbox compute (Docker/Modal) ≠ inference spend.

Key Doubts & Solutions

🔐 Selection without hidden tests — what do I use?
Use agent-written tests per sample, cross-execution (run every patch against every sample's tests), and pick the patch with highest agreement. Also try an LLM judge as a weaker arm. Report selector accuracy separately from oracle pass@N so graders see both the ceiling and your selector's effectiveness.
📊 Will 10 tasks give a real conclusion?
Not a strong one. One task = 10 percentage points, so 95% intervals will be wide. Use paired comparisons per task and bootstrap over tasks + samples. State plainly which differences are within noise. This is directional evidence, not a definitive result.
💸 Are runs too expensive for $100?
Likely at frontier model prices. Pilot one task first, then choose a cheaper model for the pool. Cost and sample count are the variables you're studying — fewer tasks is acceptable, fewer arms is not.
🔧 What if runs fail for infrastructure reasons?
Log them as infra failures, rerun once, count rerun cost. Do not silently drop tasks. Transparency here falls under the 10% intellectual honesty grade.
🧪 Cheapest falsifier for the hypothesis?
Compute oracle pass@8 vs pass@1 on the pool you already paid for. If they're roughly equal (tasks are either always-solved or never-solved), there's no diversity to exploit and best-of-N cannot help. Zero extra spend.
⚠️ Biggest limitation?
Selector quality plus small sample size. Tested on a single model and one agent scaffold, so results may not transfer. With 2 more weeks: run all 113 tasks, cascades, early stopping, model mixing, learned selectors from trajectory features.
